# Todo State Machine API

Implement `src/app.ts` using Express.

Export one function:

```ts
export function createApp(): import("express").Express;
```

The app stores todos in memory. Each call to `createApp()` must create a fresh independent store.

## Todo Shape

Every todo response should include:

- `id`: string, generated by the server.
- `title`: trimmed non-empty string.
- `status`: one of `todo`, `doing`, `blocked`, `done`, `archived`.
- `assignee`: trimmed string or `null`.
- `createdAt`: ISO timestamp string.
- `updatedAt`: ISO timestamp string.

## Routes

### `POST /todos`

Create a todo.

Request JSON:

```json
{
  "title": "Write docs",
  "assignee": "Ada"
}
```

Rules:

- `title` is required and must be a non-empty string after trimming.
- `assignee` is optional. When omitted, `null`, or blank after trimming, store `null`.
- New todos start with status `todo`.
- Respond with status `201` and the created todo.
- Invalid input responds with status `400` and JSON `{ "error": { "code": "...", "message": "..." } }`.

### `GET /todos`

List todos in creation order.

Optional query filters:

- `status`: only return todos with this status. Unknown statuses are invalid.
- `assignee`: match the normalized assignee exactly.

Invalid filters respond with status `400` and the error shape above.

### `GET /todos/:id`

Return one todo. Missing ids respond with `404` and the error shape above.

### `PATCH /todos/:id/status`

Transition one todo.

Request JSON:

```json
{
  "status": "doing"
}
```

Valid transitions:

- `todo` -> `doing`, `archived`
- `doing` -> `todo`, `blocked`, `done`
- `blocked` -> `doing`, `archived`
- `done` -> `archived`
- `archived` has no outgoing transitions

Rules:

- Unknown target statuses respond with `400`.
- Missing ids respond with `404`.
- Invalid transitions respond with `409`.
- A failed transition must not mutate the todo.
- A successful transition updates `status` and `updatedAt`, then returns the updated todo.

```sh
pnpm test
```
